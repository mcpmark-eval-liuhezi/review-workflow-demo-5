# Contributing Guide

## Workflow

1. **Read the docs** — start with the README and this contributing guide.
2. **Branch from `main`** — create a feature branch for your change (e.g. `add-contributing-guide`).
3. **Make your change** — one logical change per commit.
4. **Open a pull request** into `main` with a short description of what you changed and why.
5. **Respond to review** — during code review you may revise the change in commits on the PR branch, or ask clarifying questions.
6. **Submit a line-level comment review** — see the review samples for how inline comments are anchored to specific changed lines and summarized with an overall feedback message.

## Reviewer tips

- Reviewers review line by line, then cross-check that the overall description makes sense.
- A reviewer may suggest improvements instead of blocking the merge.
- The `All changes must be reviewed before they are merged.` rule in this file is the default policy for every merge, so an un-reviewed change will never be merged by a repository policy.
